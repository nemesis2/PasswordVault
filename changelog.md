# Changelog

All notable changes to the vault, newest first.

## 1.1.6 — 2026-06-29

- **Extensions — passkey attach uses the current vault revision**: when creating a passkey and **attaching it to an existing entry**, both extensions now confirm the target record is still part of the **current server revision** before writing. The approval window unlocks the vault (a fresh `index.html` fetch) when the master passwords are entered, but the user may then sit on the window while another client edits the vault; the passkey-create path already re-fetches the current revision (`_fetchVaultIndex`), and it now checks the chosen target's canonical record against that freshly-pulled record set. If the entry was edited or removed elsewhere in the meantime, the ceremony aborts with "Vault changed since this window opened — close it and try again" instead of firing the atomic `delete_rec=<old>&data=<new>` against a record the server no longer has (which would phantom-delete nothing and re-add the entry as a stale duplicate, orphaning the other client's edit). Create-new-entry passkeys were already committed on top of the freshly-fetched revision and are unchanged. Applied byte-for-byte to the shared `vault-session.js` in both the Firefox and Chrome/Edge builds.
- **Version sync**: PWA app, Firefox extension, Chrome extension, the terminal client (TUI), and the standalone Node server (`server.js`) all bumped to **1.1.6**.
- **Extensions — UI consistency pass**: a cosmetic cleanup across the two extension windows (the toolbar popup and the passkey approval window), no behavior change, applied byte-for-byte to both the Firefox and Chrome/Edge builds. The self-test notice's warning glyph is now the text-presentation `⚠︎` (`&#x26A0;&#xFE0E;`), matching the integrity notice and the PWA convention instead of a bare emoji `⚠`. The popup's auto-lock-disabled stopwatch dropped a one-off `#ff4d4f` red for the shared `--red` token, so `popup.css` now uses a single red. The approval window's inline palette/metrics were realigned to the popup's design tokens: its border grey (`#2a2f3a` → `#2c313b` = `--border`), its Deny-button fill (→ `#21252e` = the popup's neutral-button `--panel-2`), and its control corner radius (`8px` → `6px`) now match the popup. (The approval window keeps its own slightly larger base font and the green Allow button — deliberate dialog/semantic choices.)
- **Extensions — shared session core (`vault-session.js`)**: the session/crypto half that was duplicated between Firefox's `background.js` and Chrome's `offscreen.js` (~400 lines copy-pasted: the decrypted `SESSION`, the v6 unlock/decrypt loop, the hostname matcher, the clipboard auto-clear, the WebAuthn passkey create/get/precheck ceremonies + authenticated write + integrity-manifest re-sign, and the crypto self-test) is lifted into a new `vault-session.js`, shared **byte-for-byte** by both extensions (loaded by the Firefox background page and the Chrome offscreen document). Each `background.js`/`offscreen.js` is now the thin platform host: the toolbar icon/badge, idle auto-lock, tab autofill, approval-window plumbing, the message handler, and the `unlock`/`abortUnlock`/`lock`/`_progress` wrappers. The shared `_unlockInner` returns a uniform result (`{ ok, count, vaultUrl, hosts, integrityFailed }`) and each host paints its own UI from it. No behavior change (no standalone version bump — ships in 1.1.6); collapses ~2000 duplicated lines to one source of truth, removing the drift risk in the security-sensitive unlock/passkey/signing paths. Two pre-existing Firefox/Chrome divergences (a stale `SESSION.vaultUrl` on lock; a missing `isNote` flag on a passkey-created entry) are resolved by the unification. Also removed the stale `firefox-extension/CHROME-PORT-PLAN.md`. Verified: extension self-tests + the full `run-tests.sh` suite (client crypto/logic, server protocol, 12/12 PHP↔Node parity) all pass.
- **Extension — vault integrity failure handling**: the browser extensions now verify the vm1 integrity manifest HMAC after every unlock (two additional Argon2id derivations over the manifest salts, run in parallel on the existing worker pool). If the HMAC does not match the decoded record set — indicating tampering, corruption, or a mismatched manifest — the toolbar badge turns red **✗** on every tab (matching the crypto self-test failure indicator), the popup disables auto-fill, clears and disables the search/filter input, and replaces the entry list with a red notice ("Vault integrity check failed — auto-fill is disabled. Lock and re-unlock to retry, or inspect the vault."). A clean re-unlock clears the failure and restores normal operation. An absent manifest (unsigned vault) is left as-is without triggering the failure path.
- **Extension — crypto self-test failure badge**: when the extension's Argon2id / AES-GCM / ChaCha20-Poly1305 / Twofish / Serpent self-test fails at startup, the toolbar badge already turned red **✗**; the popup now also disables both password fields and the Unlock button and shows the failing primitive(s) in a red notice, preventing any unlock attempt on a broken crypto environment.
- **About modal version link**: the version number shown in the About modal (PWA, and both the Firefox and Chrome/Edge extension popups) is now a clickable link to the project's GitHub repo (`https://github.com/nemesis2/PasswordVault`).
- **Version sync**: PWA app, Firefox extension, Chrome extension, the terminal client (TUI), and the standalone Node server (`server.js`) all bumped to **1.1.4**.
- **UI/UX consistency pass**: an accessibility + cosmetic cleanup across the PWA, no behaviour or record-format change. Added an `aria-label` to the icon-only 📋 copy button; **double-submit guards** that disable Audit / Passkeys / Export CSV while their decrypt-all runs (matching the existing Change Passwords / KDF buttons); unified user-facing string wording (em-dash error separators in toasts and alerts, a single text-presentation `⚠︎` warning glyph everywhere). Stylesheet tidy-up: a new `--on-accent` variable replaces hardcoded `#fff` on accent/danger surfaces (and two hardcoded danger `rgba()`s now follow the theme via `--danger-rgb`); the three near-identical entry "active" states (`.selected` open entry / `.entry-selected` multi-select / `.pal-active` palette-nav) now share one base rule with only their genuine differences kept; a new `--r-sm` radius token replaces 17 scattered `4px` literals; and the duplicated `.card-title` / `.gen-title` section-label typography is de-duplicated.
- **Command palette (Ctrl-K)**: the search overlay doubles as a command palette — open it with **Ctrl/⌘-K** (or **?**, or the 🔍 toolbar button). Fuzzy-find entries by name, move through results with **↑/↓**, and press **Enter** to open the highlighted entry; with one highlighted you can act without leaving the keyboard — **Ctrl-C** copies its password, **Ctrl-U** its username, **Ctrl-E** opens it for editing (⌘ on a Mac). A leading **`>`** switches to **command mode**: a fuzzy-filtered list of vault actions (New entry, Lock, Export / Import, Audit, Passkeys, Trash, Change Passwords / KDF, Toggle theme, and more) — actions needing an unlocked vault are dimmed until both passwords are entered, and About-panel actions open it scrolled to the right section. The same scoped prefixes as plain search apply inside the palette (`#tag`, `@note`, `!field`).
- **Backup retention by age + count**: `bak/` is now pruned on every write in two passes — first drop any backup older than **60 days**, then keep only the newest **100** (oldest removed first; the count cap was 50, age-based pruning is new). Both limits are overridable per-deployment via the `VAULT_BAK_KEEP` / `VAULT_BAK_MAX_AGE_DAYS` environment variables (`0` disables that dimension). All three write clients honor them identically — `post.php`, `server.js`, and the TUI (`tui.node/lib/vault.js`) — so the shared `bak/` directory is pruned the same way whichever client wrote last.
- **Version sync**: PWA app, Firefox extension, Chrome extension, the terminal client (TUI), and the standalone Node server (`server.js`) all bumped to **1.1.3**.
- **Client-side unit tests (`test-client.js`)**: a new Node-based test suite for the crypto + pure logic in `javascript.js` — loads the unmodified browser source into a `vm` context (same host-global shim pattern as `moved/repad-vault.js`) and exercises the v6 name+payload encrypt→decrypt round-trip, `_assembleRecord` shape vs `_isValidV6Record`, `_estimateBits`, `computeTotp` against the RFC 6238 SHA-1/256/512 test vectors, the manifest HMAC (`_manifestHmacHex` + `_constTimeHexEq`), `_normalizeTags`, and `_padPlaintext`. Uses a cheap Argon2id cost (8 MiB / t=2) so it runs in seconds. Run after touching the crypto/record helpers.
- **Version sync**: PWA app, Firefox extension, Chrome extension, the terminal client (TUI), and the standalone Node server (`server.js`) all bumped to **1.1.1**.
- **Secure notes (entry type)**: entries now have a **type** — `login` (default) or `note`. A secure note is just a title + an encrypted body (Notes), tags, and custom fields, with the URL/username/password/2FA/generator UI hidden in both the form and the decode panel. The type lives inside the encrypted payload JSON (`fields.type`) — no v6 record-format change, and `login` is the absent-key default (existing entries are untouched). Note entries get a 📝 grid badge and are skipped by Audit (no password).
- **Bulk operations (multi-select)**: a grid **select mode** (toggle beside Group A–Z) to act on many entries at once — **Delete** (one atomic, Undo-able `restore` write; backed up to `bak/`), **Tag** (decrypt → merge tags → re-encrypt → one `restore` write), and **Favorite** (localStorage toggle). Selection is in-DOM only and is cleared on lock/rebuild. Deleting *every* entry at once is refused (a `restore` write can't be empty).
- **Passkeys (WebAuthn)**: the browser extensions now act as a WebAuthn authenticator — they override `navigator.credentials.create/get`, generate an ECDSA P-256 key pair on **create**, encrypt it into a new vault entry (`fields.passkey` inside the existing v6 payload — no record-format change; `url: passkey://<rpId>`), and **sign** site challenges on get (`signCount` stays `0`, so signing in is read-only). Creating a passkey prompts per-write for the two master passwords + the Basic-Auth write password; nothing is persisted. The **web app only displays** a stored passkey (a 🔐 decode-panel row + a Vault Tools → **Passkeys** inventory) and can **delete** it (strips the passkey, keeping the rest of the entry, or removes the whole entry if empty) — it never creates or signs. `post.php` / `server.js` now accept `chrome-extension://` / `moz-extension://` origins in the CSRF same-origin check (writes still Basic-Auth gated) so the extension can commit the new record. New shared extension files: `webauthn.js` (CBOR/COSE/attestation builders), the `crypto-vault.js` encrypt path, content-script interceptors, and a per-write approval window. Extensions bumped to **1.1.0**.
- **Installable PWA**: added a web-app manifest (`manifest.json`) and a 1024×1024 icon (`icon.png`), linked from the page's `<head>`, so the vault can be installed from the browser (address-bar install icon, or ⋮ → Install) and runs in its own window with a home-screen/launcher icon. Works with no TLS over `http://localhost`, which counts as a secure context.
- **Service worker (`sw.js`)**: optional, installed at the instance root. Speeds repeat loads of the heavy non-secret code assets (`javascript.js`, `argon2-worker.js`) and gives the PWA a graceful offline-fallback page. **Never** caches the navigation document — `index.html` embeds the ciphertext DB and stays network-only (consistent with `no-store`), so the encrypted vault is never written to Cache Storage. Exposes a `GET_ASSET_HASHES` message hook for a future code-integrity check.
- **TOTP — full `otpauth://` spec + Steam Guard**: the engine now parses `digits`, `period`, and `algorithm` (SHA-1/256/512) from an `otpauth://` token and supports **Steam Guard** 5-character codes; the countdown ring honors the entry's period. Plain Base32 secrets keep the 6-digit/30s/SHA-1 defaults. The QR scanner stores the full URI when it carries non-default params. Verified against the RFC 6238 SHA-1/SHA-256 test vectors. The Chrome/Edge and Firefox extensions and their period-aware countdown were updated to match.
- **KDF auto-tune**: a **Calibrate** control in Change KDF Parameters benchmarks Argon2id on the current device and suggests an iteration count for a target time (default 500 ms).
- **KeePass + 1Password import**: import entries from a **KeePass 2 XML** export and a **1Password `.1pux`** archive (a ZIP read client-side via `DecompressionStream` — no library), merged into the vault via the count-flexible `restore` write. (Encrypted `.kdbx` binary is out of scope by design — export to XML/CSV first.)
- **Light theme**: a 🌙/☀ toggle (next to About) switches a light palette via CSS variables, persisted per-instance in `localStorage`.
- **Entry monogram avatars**: each revealed entry button (and search result) shows a CSP-safe local "favicon" — a colored first-letter circle, color hashed from the name (no third-party favicon fetch — `connect-src 'self'`).
- **Docs**: split a **`SECURITY.md`**, **`THREAT_MODEL.md`**, and **`CONTRIBUTING.md`** out for the public repo; added **`verify-bundles.sh`** (checks the worker/main-thread Argon2id are byte-identical and the cipher globals are present) and a running **`suggestions.md`** roadmap. Added **`export-public.sh`** to regenerate a secrets-free publishable copy.
- **Password history**: editing an entry archives the previous password (with a timestamp, newest-first, capped) inside the encrypted payload; viewable + click-to-copy in a collapsible decode-panel row.
- **Custom fields**: arbitrary label/value pairs per entry (optionally marked *secret* → masked + click-to-copy), stored in the encrypted payload.
- **Password-age audit**: Audit now also flags passwords not changed in over a year (entries carry a `pwModified` stamp set on create / password change).
- **Favorites**: star an entry to pin it to the top of the grid (under a ★ group header); persisted per-instance in `localStorage` keyed by a non-reversible name-hash. Toggle via the decode-panel ☆ button or the **F** shortcut.
- **Trash / soft delete + restore**: deletions move to a new server-side `trash` file (30-day retention, ciphertext only) and can be restored or permanently purged from a new Vault Tools → **Trash** view.
- **Hardening**: `.htaccess` and the live nginx config now also deny direct access to `trash`.
- **Change KDF Parameters**: tune vault-wide Argon2id cost (memory/iterations) and re-encrypt the whole vault, persisted atomically in a new `kdfparams` file.
- **Import / Restore**: replace the whole vault from an exported `.lines` file via a new count-flexible `restore` write mode.
- **CSV export / import**: migrate to/from other password managers. *Export CSV* writes every entry as plaintext (gated behind a hard warning + confirmation that it strips all protection); *Import CSV* adds entries from a CSV exported by another manager (Bitwarden / Chrome / 1Password column aliases), re-encrypting each row and merging it into the existing vault via the `restore` write.
- **Search**: the `!field` (custom-field) scope no longer indexes fields marked *secret*, so a masked value can't be surfaced by searching for it.
- **Length-hiding payload padding**: plaintext is padded to a 256-byte bucket before encryption so ciphertext length no longer leaks password/note length.
- **Six-tier password strength meter**: added two segments and the combined two-key vault-key bar that gates the New button below a minimum entropy.
- **Change Passwords UI**: new-password fields gain live show/hide, match, and strength feedback.
- **Argon2id worker-pool sizing**: mobile core cap, device-memory budget, and per-derivation retries to stop dropped name decrypts under memory pressure.
- **Keyboard shortcuts + About tooltips**: added a shortcuts reference section and hover tooltips in the About modal.
- **About modal version**: the About modal now shows the app version, read live from `manifest.json` (with a baked-in fallback for the offline/read-only copy).
- **Chrome / Edge extension**: new Manifest V3 port of the Firefox autofill companion (`chrome-extension/`), reusing the crypto, content script, popup UI, and icons verbatim. The persistent session + Argon2id worker pool + DOMParser + clipboard live in an offscreen document (the MV3 stand-in for Firefox's background page); the service worker owns the toolbar icon/badge, idle auto-lock, tab autofill injection, and message routing. Builds via `chrome-extension/build-zip.sh`.
  - The site-match badge uses an explicit dark background (Chrome ignores a transparent badge and falls back to red).
  - Popup scrollbars are now thin (both Chrome and Firefox) instead of the thick OS default.
- **Terminal client (`tui.node/`)**: brought in sync with the current vault — it now reads the **vault-wide Argon2id cost** from `kdfparams` (it previously hardcoded 64 MiB and could no longer decrypt the 128 MiB default vault), applies the same **length-hiding 256-byte padding** when writing records, and **preserves `tags` / custom fields / password history / password-age** on edit (archiving the old password on change) instead of dropping them.
- **Version sync**: PWA app, Firefox extension, Chrome extension, and the terminal client bumped to **1.0.3**.
- **Documentation**: the main `README.md` now covers the optional **browser extensions** (Firefox + Chrome/Edge autofill companions) and the **terminal client** (`tui.node/`), with an architecture-table row for each; the extension docs note they work against either backend (PHP `post.php` or the standalone Node `server.js`).
- **Hardening**: `.htaccess` now also denies direct access to `manifest` and `kdfparams`.
